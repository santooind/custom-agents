ERD 1 — Original Custom-Heavy Model v3.2 Legacy

10 custom tables · Initial design · Superseded

The original v3.2 design created 10 custom tables, including custom request tables that duplicated native sc_req_item functionality. This diagram is retained for historical reference to show the complexity that was eliminated.

  • vault_application + vault_sub_application → consolidated into vault_scope
  • vault_onboarding_request → replaced by native sc_req_item
  • vault_dynamic_access_request → replaced by native sc_req_item
  • vault_transaction_log → replaced by native IntegrationHub logs

ERD 2 — Final Lean Custom Model v5.1 Final

ERD 4 — Integration Flow Diagram v1.1

ServiceNow ↔ Terraform ↔ Vault · Dual integration paths

This diagram illustrates the two distinct integration paths:

  • Path A (Async): ServiceNow → Terraform Cloud → Vault (for Onboarding & Dynamic Access provisioning)
  • Path B (Sync): ServiceNow → Vault KV v2 API directly (for Static Secret CRUD — Epic 2)

The Terraform path uses callbacks (webhooks) with a polling fallback. The Vault direct path is synchronous with immediate response.

Model Evolution Summary

v3.2 (10 tables) → v4.0 (5 tables) → v5.0 (6 tables) → v5.1 (6 tables, field-complete)

v3.2 Table v5.1 Equivalent Action Rationale
vault_application vault_scope Consolidated Single table with u_is_sub_application boolean eliminates join + reduces hierarchy
vault_sub_application
vault_onboarding_request Native sc_req_item + 7 fields Eliminated Native RITM gives approvals, SLAs, portal widgets, activity streams for free
vault_dynamic_access_request Native sc_req_item + 7 fields Eliminated Same as above — one RITM table serves both catalog items
vault_transaction_log IntegrationHub native logs Eliminated HTTP execution tracing is a platform capability, not a custom concern
vault_scope_environment vault_scope_environment Retained No native equivalent for per-environment onboarding status tracking
vault_database_registry vault_database_registry Retained (slimmed) Removed u_owner_application — ownership context comes from requesting scope
vault_dynamic_access vault_dynamic_access Retained Essential governance record: what access is ACTIVE or DISABLED
vault_secret_metadata vault_secret_metadata Retained + corrected v5.1 restored 6 missing fields (description, labels, rotation/deletion tracking)
vault_audit_event vault_audit_event Retained + corrected v5.1 restored 5 missing fields (resource_type, version, ip_address, timestamp, source_record) + Event Types list
